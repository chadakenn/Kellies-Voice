# Kellie's Voice v0.16.6

**TV alert connection reliability update, released for community testing.**
Targets [issue #78](https://github.com/chadakenn/Kellies-Voice/issues/78)
reported on Philips Android TVs with v0.16.5 after TV standby or an HA YAML reload.
It preserves the five previously released v0.16.5 community improvements.

## What changed

- **Resume TV alerts** now cancels an existing TV alert WebSocket and creates
  a fresh connection instead of accepting a stale socket as connected.
- A 15-second receiver watchdog detects missing subscription readiness
  (45-second setup deadline) and uses Home Assistant's authenticated
  `ping`/`pong` heartbeat to detect a half-open but seemingly connected
  WebSocket (30-second missed-response threshold). Bounded retries apply.
- Repeated ordinary service starts keep a healthy receiver connected and
  allow a still-pending authentication to complete normally.
- Late callbacks from a replaced socket cannot overwrite the state of the
  new receiver. Explicit HA authorization errors are preserved instead of
  forcing endless reconnect loops.
- These changes affect the **TV alert receiver only**. No new Android
  permissions, microphone capture, wake word, or audio focus changes.

## Installation

On the Android TV, open **Kellie's Voice → Settings → Check for app updates**.
Update to **v0.16.6** (versionCode 23) using the existing signed APK, without
uninstalling. Update the matching **HACS Kellie's Voice integration** to 0.16.6
and restart Home Assistant if an integration update is offered.
