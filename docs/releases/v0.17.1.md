# Kellie's Voice v0.17.1

**Android TV:** signed versionCode 56 · **Home Assistant HACS integration:** 0.17.1.

## Hotfix

- Fixed **Okay Nabu wake word** activation showing **"Configure Home Assistant before enabling the wake word"** when a TV was already paired through the new owner-approved renewable login introduced in v0.17.0.
- The Compose Settings switch, the legacy Settings dialog, the wake-word background service and foreground-relaunch restoration now share one token-free check. An active owner-approved TV grant is accepted without a manually entered Home Assistant URL/token.
- Existing manual Home Assistant connections still work. If the renewable login was revoked, expired beyond recovery, or never activated, the wake word remains blocked. Crucially, a revoked renewal grant **never falls back to an older saved manual token**.
- Added Android JVM and HA repository regression tests for both login modes and the previously inconsistent Settings screen.
- No changes to wake phrase/model, microphone permission handling, camera feeds, dashboard URLs, Quick Actions or user preferences.

## Updating from 0.17.0

1. Update **Kellie's Voice** in HACS to **0.17.1** and restart Home Assistant (the HA component is otherwise unchanged; this keeps version labels matched).
2. In the TV app, use **Settings → Check for updates**, or install the official **signed** v0.17.1 `app-release.apk` over the existing signed installation.
3. **Do not uninstall, clear data, re-pair, paste a new token, or delete the working owner-approved login.**
4. Open **Settings → Voice & microphone → Wake word (Okay Nabu)** and enable it. Grant microphone and **Display over other apps** permission if Android asks.
5. The saved wake-word opt-in should be restored on a visible app launch after reboot where Android allows microphone foreground services; Android 14+ may prevent immediate microphone start directly at boot.

See [v0.17.0 release notes](v0.17.0.md) for all new public features and known owner-approved pairing limitations.
