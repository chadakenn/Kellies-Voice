# Kellie's Voice v0.17.0 — DRAFT release notes (NOT PUBLISHED)

> ⚠️ **QA candidate only.** This is NOT a release and is not safe to publish
> from the combined branch until the signoffs in
> [v0.17 acceptance checklist](../qa/v0.17.0-combined-onn-qa.md) are complete.
> Public stable v0.16.14 remains the supported release.

## What's new in the candidate

- **TV Quick Actions:** up to four large remote-selectable home-screen
  buttons configured in Home Assistant. Choose a button label, allowed
  light / scene / script, action, and icon. Buttons execute only a HA-owned,
  authenticated, permitted service call; the TV can submit only a slot.
- **Automatic icons:** use the selected HA entity's Material Design Icon
  name or choose an override from the HA device Configuration card.
  The TV maps common MDI icons to built-in offline symbols. Unsupported
  icons show a generic symbol; exact full MDI artwork is not bundled.
- **Voice captions:** idle screen is dedicated to Quick Actions. Listening,
  recognized speech and the spoken reply appear temporarily as CC-style
  overlays. Spoken captions remain while TTS is playing.
- **Appearance:** six themes; local persistence verified on the onn 4K Pro.
- **Owner-approved pairing QA:** experimental two-screen code confirmation,
  TV remote proof and renewable HA login in the separately installed QA
  package. This is **not** a general/public onboarding path until security
  and authorization review is complete.
- **Connection recovery patches:** TV boot receiver and floating voice
  overlay can consult the owner-approved renewable login. Changes passed
  code tests; unattended TV boot and floating overlay still require the
  patched signed APK to be installed and tested on hardware.

## Requirements

- Matching Android TV APK and Home Assistant custom integration from an
  approved, version-matched release. **HACS does not install the Android APK.**
- An explicitly authorized HA account and existing supported Assist pipeline.
  For v3 experimental token renewal, HTTPS is required. Local HTTP-only
  secure renewable login is still research (#262).
- Mic and display-over-other-apps permissions only where explicitly opted in.
  The app never turns on wake listening automatically by installing an update.

## Important known limitations and pending verification

- Passive camera alert windows do not intercept the remote's Back button;
  an explicit opt-in interactive camera mode is tracked in #264.
- The real credential's refresh, expiry/revocation and multiple-TV isolation
  must pass hardware/security review (#214). Do not treat normal HA Users
  permissions as restricted only to the selected four actions.
- The new TV icon/Quick Actions/CC rendering, remote focus, unattended boot
  restore and floating voice overlay are **not yet physically accepted** on
  the final signed combined APK.
- Do not replace stable Android credentials or a working HACS installation
  just to sample unverified development changes.

## Release / rollback procedure (after approval only)

1. Confirm all required checks green on the exact final merged commit, and
   independently review the OAuth/Keystore/HA permission path.
2. Run signed QA workflow on the candidate with `publish_release=false`;
   install signed `com.example.tvvoiceprobe.qa` over the previous QA
   package, preserving pairing and stable `com.example.tvvoiceprobe`.
3. Confirm HA Quick Actions, icons, TV speech, camera alerts, and all
   negative security tests on a real TV. Record failures before any release.
4. Prepare versionCode/versionName bump, matching HACS manifest, installation
   / upgrade / rollback guide, checksums and redacted screenshots.
5. Only with explicit maintainer approval, publish a public prerelease.
   **Never** automatically push experimental code to main or make it Latest.
6. Roll back by reinstalling the known-good stable app and matching HACS
   version; preserve personal settings and never copy tokens across packages.
