## Changes

### Smoother Home Assistant dashboard loading
When opening an HA dashboard (rather than the Frigate website), Kellie's Voice masks the initial WebView behind a black loading screen while the HA frontend navigates through login, its default page and the saved dashboard. It reveals the target only after the configured path and frontend are present and stable. If automatic login stalls, a **Sign in manually** button becomes available after about 15 seconds, avoiding an inaccessible login on TVs that require interactive sign-in. This does not bypass authentication, enable untrusted navigation or pass credentials in the URL.

### Show/hide the configured TV dashboard from Home Assistant
The companion integration adds **`kellies_voice.show_dashboard`** and **`kellies_voice.hide_dashboard`** actions. Both **require one TV pairing ID**. Use Home Assistant → Developer tools → Actions:

```yaml
action: kellies_voice.show_dashboard
data:
  device_id: YOUR_TV_PAIRING_ID
```

```yaml
action: kellies_voice.hide_dashboard
data:
  device_id: YOUR_TV_PAIRING_ID
```

Optionally add `dashboard_path: /mobile-command/bedroom` (or another same-server route) to open a different HA dashboard from each trigger. Changing the route while an on-demand dashboard is open switches views. `dashboard_path` is a **path only**, never a full hostname, URL, token, query string or redirect target. Omit it to use the TV's default configured source. The TV uses its **already configured** Home Assistant server/screensaver source. The service payload is limited to the authenticated, read-authorized TV event subscription and includes **only the matching TV ID**. No arbitrary URL, token, or browser control is accepted by these actions. `hide_dashboard` closes only a dashboard opened on demand, never disables ambient mode or automatically closes a running Android dream.

**Prerequisites:** Enable the on-TV screensaver, configure its source, allow Display over other apps, enable TV alerts, and verify the TV alert receiver is connected. Install the **matching** TV app and HACS integration. Android/TV firmware can still prevent background overlays or foreground-service launch; HDMI behavior varies.

### Philips OLED documentation / compatibility notes
A [community report on Issue #261](https://github.com/chadakenn/Kellies-Voice/issues/261#issuecomment-6562897320) confirmed dashboard trusted-network login, D-pad/Back controls, overlays on TiviMate and HDMI, and camera popups on a Philips 55OLED856/12 OLED and 65PUS8507/12 LED.

The OLED TV can display a Philips vendor bouncing logo **above** an otherwise-running Kellie's Voice screensaver. The tester used a one-minute Android timeout and a changing HA dashboard; these are **not guaranteed panel protection** and should not disable manufacturer safeguards. One unreproduced whole-TV freeze was reported with an unknown cause. Automatic screensaver startup after a *full TV restart* still needs physical validation. [Full Philips caution and diagnostics](../wiki/Cameras-and-Frigate.md#philips-oled-factory-screensaver-covering-the-dashboard-community-report-november-2026).
