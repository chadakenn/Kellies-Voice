## What's new in this candidate

1. **One redesigned Settings interface in QA/development builds.** Larger TV-friendly controls, D-pad focus and Compose screen on the QA route; the legacy recovery path remains in the code. Public release routing requires explicit visual/functional validation.
2. **Six consistent color skins**, with Copper Glass as unchanged default, Jade Terminal and Neon Obsidian optional. Applies to Compose Settings, main TV page and compatible overlays/popups, subject to physical theme QA.
3. **Redesigned fullscreen Kellie's Voice home.** Clear HA connection status (without showing the saved HA URL), readable reply and speech cards, preserved TALK/STOP/SETTINGS and theme-based remote focus.
4. **Four optional, editable Quick Actions for microphone-free TVs.** Configure each TV's labels and light/scene/script action in Home Assistant integration Options; the fullscreen TV reads slot names and sends only chosen slots over its already-authenticated WebSocket. HA owns and permission-checks entity/action; the floating voice popup is unchanged. Empty by default. No locks, garage doors, alarms or arbitrary domains; owner-configured scripts should be reviewed.
5. **Existing stable capabilities retained:** opt-in Okay Nabu local wake word, Assist push-to-talk and audio ducking, opt-in announcements and camera popups, Frigate screensaver and live camera full-screen/back controls, reconnection and updater. These are regression-test targets, not newly invented functionality.

## Required headline feature: #193 no-typing onboarding (NOT YET IMPLEMENTED)

**Do not publicly publish this candidate until #193 is completed and tested.** The [#197 → #200 → #201 → #202 → #203](https://github.com/chadakenn/Kellies-Voice/issues/193) draft stack currently supplies PKCE primitives, temporary LAN discovery, matching code, explicit TV OK proof and ECDH/AES-GCM primitives, but **NOT** actual owner-authorized login, secure credential provisioning, access/refresh-token lifecycle or verified connection.

Expected first-install experience: **open TV app → Waiting for Home Assistant → in Home Assistant add Kellie's Voice and select discovered TV → explicitly authorize as a HA user → compare matching code → press one OK on the TV remote → encrypted one-use token transfer → authenticated Assist and TV alerts prove they work → Connected**. No typed TV URL, access token or pairing ID. Retain existing manual method as a fallback across VLANs.

**Security requirements:** HA-supported OAuth authorization code + PKCE S256, documented client identity and redirect URI, HA owner consent, secret transfer only over transcript-bound authenticated AEAD after both confirmations, revocable refresh credentials (not a copied admin/long-lived frontend token), Android Keystore storage, safe refresh/revoke and HA login proof. OAuth refresh tokens are bound to a HA user, not inherently narrow per-TV entity scopes. Never mark an mDNS-discovered TV as authenticated. Do not silently overwrite working manual credentials or enable microphone, wake word or announcements. <https://contributors.home-assistant.io/core/internals/auth-api/>

## Safe tester upgrade

**Before installing:** make a Home Assistant backup. The Android and HA components are separate and must be updated **together** for Quick Actions. Installation of this in-development HACS component directly into a production HA instance can affect working automations, so use a test HA installation or intentional maintenance window.

1. Opt into development updates **separately** for the TV and HACS. The beta must be a **signed public GitHub prerelease**, not a disposable Android debug APK. Existing updater requires a GitHub release with `app-release.apk` and `update.json`.
2. Install signed Android `v0.17.0-dev.1` over v0.16.14 **without uninstalling/clearing data**. Signature and package identity must match existing stable. The published code 55 cannot be downgraded in place to code 54; wait for a newer code stable or restore an authorized device backup if leaving beta.
3. In HACS explicitly choose matching `0.17.0-dev.1` using its prerelease/manual version selector; restart HA and verify the existing Kellie's Voice device/entities are preserved. Do NOT install separate second integration.
4. In **Settings → Devices & services → Kellie's Voice → desired TV → Configure**, optionally set 1–4 Quick Actions using `light.*`, `scene.*` and `script.*` and short labels. Start with a harmless light. Do not use a security-sensitive script.
5. Open the **full app screen** and press D-pad Up from TALK/STOP/SETTINGS to reach the buttons. The floating voice overlay does not show them.
6. Report pass/fail and TV model/Android version plus non-sensitive diagnostics in GitHub. Never publish camera footage, access tokens, local URLs or pairing UUIDs.
