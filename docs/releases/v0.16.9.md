# Kellie's Voice v0.16.9

**Public community verification release · October 24, 2026**

This version includes two improvements since v0.16.8. Both passed automated Android unit tests, Home Assistant integration tests, and HACS checks. **The new behavior still needs physical device testing.**

## New in v0.16.9

- **Room-aware Assist (#50):** When **Home Assistant layout** is ON in Kellie's Voice, the TV learns the *Home Assistant device-registry ID* from its registered control entities and includes it in subsequent Assist pipeline requests. This may allow the Assist agent to use the TV's assigned area for phrases like “Turn on the lights in here.” The registry ID and alert-targeting pairing ID are intentionally different. No ID available or layout sync OFF means the existing behavior is preserved.
- **Automatic TV alert recovery (#86, issue #78):** During an HA restart, a TV may connect before HA has finished creating its alert controls. The HACS integration now returns a specific temporary-not-ready response instead of treating this as a permissions failure. Android retries with bounded backoff. **Actual** invalid/unauthorized tokens, unpaired IDs, and users without the required read permission are still rejected. Alerts missed while offline are not replayed.
- **HACS banner (#58)** and beginner Wiki/YAML cookbook source (**#85**) documentation are included.

## Installation

1. On the TV, use **Kellie's Voice → SETTINGS → Check for app updates**, or download this release's **signed `app-release.apk`** and install *over* the previous signed APK. **Do not uninstall:** that deletes the saved Home Assistant connection. Android `versionCode` is now **26**.
2. In **HACS → Kellie's Voice**, update the matching custom integration to **0.16.9**, then **restart Home Assistant**. HACS does not install the Android APK.
3. Assign the paired TV an **Area** under **Home Assistant → Settings → Devices & services** (if desired) and enable **Home Assistant layout** in the TV app. Reconnect Kellie's Voice once to learn its registry ID.

## What to test

- **#50 room context:** With your TV assigned to an area, ask a room-relative command such as “Turn on the lights in here.” Confirm **only** the correct area's lights respond. Also check normal talk/stop and that other Assist devices behave normally.
- **#78 automatic recovery:** Leave TV alerts enabled, restart HA, and **do not press Resume TV alerts**. After HA is loaded, confirm **TV alert receiver connected** becomes ON automatically and send a **new** announcement to verify an on-TV popup. The sensor alone is not proof of delivery. If it fails, the manual workaround remains **TV app → SETTINGS → TV alert status → Resume TV alerts**.
- **#71 known Philips microphone limitation:** v0.16.8's allowlist still did **not** prevent silent recording on both tester Philips TVs. This issue is **unresolved** in this release. Report the app's actual Android microphone diagnostic list without tokens or private data.

If your TV behaves differently, report hardware/OS version, app and HACS versions, exact non-sensitive status text, and whether Home Assistant restarted. This is a testable release, **not** a guarantee of 24/7 background delivery or universal microphone support.

Follow-up listening, wake words, Frigate screensaver dashboard and actionable announcement buttons remain **experimental / not shipped**.
