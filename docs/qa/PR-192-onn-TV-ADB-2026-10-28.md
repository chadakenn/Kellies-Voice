## Bugs and compatibility gaps

1. **FAIL: initial D-pad focus.** On first entering Compose, Down sometimes failed to move from the Home Assistant category. The hierarchy reported focus on the footer instruction even while a category appeared selected. Right/Left recovered navigation; exact device-timing cause unproven.
2. **FAIL: stale Home Assistant rejection notice.** After HA rejected an unsupported style change, the old error continued to show despite later successful Night Signal, Aurora, and popup-position writes.
3. **Compatibility gap: Neon + installed HACS.** The existing HA `Overlay style` selector supports only Copper Glass, Compact Charcoal, Night Signal, and Aurora Glass. Sending Neon produced an explicit style rejection. On reopening Compose, Aurora was selected. The new fifth-style HA integration must be separately installed/verified before considering this fixed.

### Code changes after this ADB run (not yet device-verified)

- `ComposeSettingsActivity` now requests first-category focus explicitly and makes the instructional footer non-focusable.
- `LayoutWriteFeedback` and its unit tests now clear an earlier layout-rejection notice when a newer write succeeds, and prevent older late results from replacing newer feedback.
- **Do not mark either fix PASS until tested with a newer APK on the onn.**
