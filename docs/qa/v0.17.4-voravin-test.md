# Kellie's Voice v0.17.4-dev.2: volunteer TV test instructions

**Tester preview, not a public stable release.** This branch is intentionally separate from PR #300 / main. It is signed with the same stable signing identity for a normal in-place install, but should be treated as test software.

## Get the build

Open the latest successful **Build Kellie's Voice Dev APK** run from the [dev branch Actions page](https://github.com/chadakenn/Kellies-Voice/actions/workflows/dev-apk.yml?query=branch%3Adev). Sign in to GitHub to download Actions artifacts. Each artifact itself downloads as a ZIP:

- `kellies-voice-dev-signed`: contains **app-release.apk**, app ID `com.example.tvvoiceprobe`; signed with the **same certificate** as the stable release, version **0.17.4-dev.2**, build **60**. Installs **over** v0.17.3 with existing pairing and app preferences preserved (unless Android prevents the install). Do not uninstall the current app.
- `kellies-voice-hacs-dev`: contains the development `kellies_voice` Home Assistant integration, manifest version **0.17.4-dev.2**. Extract it so that the files end up at `/config/custom_components/kellies_voice/` (for example, `manifest.json`, `services.py` directly in that directory), replacing the previous integration files. Consider copying the existing directory first so it can be restored. Restart Home Assistant.
- `kellies-voice-qa-signed`: a **separately installed** app with package suffix `.qa`, useful for isolated testing but **not** for checking whether an in-place update preserves the existing pairing. It may require new setup and pairing.

The ordinary PR #300 debug APK has a **different debug identity** and is **not** the in-place replacement above. Do not flash that onto the existing signed installation.

## Test these functions

1. Confirm the installed version reads **0.17.4-dev.2** and the existing HA connection/pairing and optional screensaver settings survive the app upgrade.
2. On the **Philips 55OLED856/12 OLED**, start the configured HA dashboard from Settings/preview and then from ordinary idle, including over TiviMate and HDMI. Does the native loading screen hide the HA login/default dashboard flashes? Does the final saved dashboard appear without extra taps?
3. **Developer tools → Actions** in HA, with the TV **pairing ID** (not the HA device-registry ID), execute:

   ```yaml
   action: kellies_voice.show_dashboard
   data:
     device_id: YOUR_TV_PAIRING_ID
   ```

   Expected: an on-demand dashboard appears over TV playback if Android overlay permission and the TV's screensaver source are enabled and the TV alert receiver is connected.

4. Repeat `kellies_voice.show_dashboard` with `dashboard_path: /mobile-command/bedroom` (or another existing HA dashboard path); then switch to `/mobile-command/cameras`. Confirm the correct saved-origin pages load and the second request switches the on-demand view. Reject full URLs, queries and fragments. Do **not** paste real credentials into a dashboard path.

5. Then execute:

   ```yaml
   action: kellies_voice.hide_dashboard
   data:
     device_id: YOUR_TV_PAIRING_ID
   ```

   Expected: the **on-demand** dashboard closes and normal TV playback is visible. It should **not** disable or close an automatic Android system screensaver. Repeat the actions, and check D-pad, OK, and Back.
6. Test the **65PUS8507/12 LED** independently if possible and note any difference in overlay or HDMI behavior.
7. **Fully reboot** each TV, let idle/screensaver activation occur, and verify the HA dashboard and camera popups recover automatically without needing manual Resync.
8. If the OLED Philips bouncing logo covers the dashboard, note the approximate idle time and whether `FrigateScreensaverDream` is still active. Do **not** disable Philips' OLED panel-protection systems or leave bright static dashboards showing indefinitely. If a freeze occurs, note the preceding **Back/OK** sequence, TV firmware and whether the remote/ADB responds. One previous freeze had an unknown cause.

## Notes

- Both **TV alerts** and **screensaver** must be enabled on the TV, and **Display over other apps** permission allowed. These actions only address a **known configured TV**, via the authenticated TV alert receiver; they don't accept arbitrary dashboard URLs or tokens.
- If trusted-network/HTTPS HA login does not complete, the loading mask offers **Sign in manually** after about 15 seconds. Use that rather than relying on a hidden login form. Back exits.
- Some TV firmwares block overlay windows or background service launches, especially above HDMI; failures there need real-device evidence.
- Do not post Home Assistant tokens, full local HA URL with credentials, unredacted camera imagery, personal device IDs or private IP addresses in test reports.
- Please reply to [Issue #261](https://github.com/chadakenn/Kellies-Voice/issues/261) or [PR #300](https://github.com/chadakenn/Kellies-Voice/pull/300) with the TV model, firmware, what worked, and any reproducible failures.

**Rollback:** If the dev APK is newer than stable, Android may refuse a downgrade without uninstalling. Do **not** uninstall just to downgrade, since it would erase app data/pairing. Keep the dev build until a signed stable APK has a sufficiently high versionCode, or follow a separately verified data-preserving rollback procedure. The HA integration files can be restored from their previous directory and HA restarted.
