# v0.17.0 combined candidate: onn 4K Pro acceptance checklist

**Status: Draft PR #263 only. Not a public release.** The UI and secure
onboarding branches have been integrated on a separate review branch.
A green CI run is necessary but not sufficient. Physical TV signoff and
security review are mandatory.

## Install safely

- [ ] Run the private signing workflow manually on
  `integration/v0.17.0-combined-qa` with `publish_release=false`.
  Its `kellies-voice-qa-signed` artifact is the non-debuggable
  `com.example.tvvoiceprobe.qa` package with versionCode 55.
  **No public release or tag.** The normal PR test APK instead uses
  disposable `com.example.tvvoiceprobe.debug` signing, which can conflict
  when updating an older debug install.
- [ ] Update *only* the isolated `kellies_voice_v3qa` HA component from
  this PR's QA kit, preserve `configuration.yaml` and the separate
  stable `kellies_voice` HACS integration. Run `ha core check` and restart.
- [ ] Confirm old signed stable Kellie's Voice still launches and functions.
  **Do not uninstall stable or clear its data.**
- [ ] For a fresh signed QA install, pair again: the QA package has its
  own Android Keystore, pairing identity and credentials, separate from
  the existing debug beta. Never copy secrets between packages.

## First-run wizard: physical remote

- [ ] On first ordinary QA launch, welcome screen appears (not on star-button
  overlay shortcuts); readable on 720p/1080p; D-pad moves clearly between
  all buttons. Back and Skip never trap the user or start the mic.
- [ ] Secure pairing screen opens only when clicked. Compare eight digits
  with HA, press physical TV remote OK, approve by signed-in HA owner,
  choose dedicated login knowingly. Confirm TV activates and HA reports
  owner login success. Wrong code, cancel, timeout never issue a credential.
- [ ] Return to wizard: connection status becomes ACTIVATED. Confirm owner
  has been warned normal HA Users role has broad control over all entities.
- [ ] Request RECORD_AUDIO: Android prompt appears on first request;
  navigating back after allowing or denying still works. Grant alone must
  not record audio, turn on wake word or launch an overlay.
- [ ] Request Display over other apps: Android Settings opens to *QA package*.
  After returning, status reflects the actual system permission. If denied,
  receiver stays OFF.
- [ ] Skip / Finish closes wizard permanently for this installation; reopen
  under Compose > Home Assistant > First-time setup wizard (pair TV and
  grant permissions).

## Functional home, UI, alerts

- [ ] Assist displays CONNECTED AND AUTHENTICATED and executes an ordinary
  lights voice command. The app must not require manual URL/token entry.
- [ ] Compose opens from the **single SETTINGS** toolbar entry; Home/Voice/
  Overlay/Alerts/Screensaver/Updates categories, Back and D-pad focus all
  work, including after keyboard editing.
- [ ] Switch between the six proposed themes (Copper, Neon Obsidian,
  Jade Terminal, Aurora and remaining two). Verify on TV, voice overlay,
  announcement/camera popup, and after app restart.
- [ ] Alerts switch recognizes owner-approved Keystore login, not only
  manually stored credentials. Explicitly enable popup permission and
  alerts, then register this *QA TV* as a separate device under the
  **normal** Kellie's Voice HA integration (not the v3 QA test integration).
  Confirm real targeted announcement, optional speech, snapshot popup,
  live camera Back/focus/audio, screensaver and reconnect.
- [ ] **BLOCKED: matching experimental normal HACS integration not installed.**
  On a **disposable HA test installation with matching development HACS**
  only: configure 1, then 4 Quick Actions, verify D-pad press executes
  one and only one permitted light/scene/script action, validate label/theme
  focus and deny unauthorized entities. The QA TV home screen shows a
  Quick Actions heading/configuration hint, but the isolated v3 pairing
  integration does not supply the buttons. Do not replace production HACS
  just to test these prototype options.
- [ ] Repeat one command after TV app restart, TV power cycle, HA restart,
  Wi-Fi outage and automatic recovery. Confirm receiver and Assist separately.
- [ ] Verify renewable access-token refresh after the normal refresh cycle,
  then revoke the dedicated TV refresh credential from HA and prove the TV
  cannot quietly fall back to a stored owner's access token.
- [ ] Two TVs: isolate approvals, device IDs, renewal, alerts and Quick Actions.

## Physical onn 4K Pro QA observations (2026-10-30)

These results are from a real **signed, separately installed QA package**;
they are not blanket acceptance of the release or a substitute for CI/security
review. PR #263 remains draft.

- **PASS:** HA-owner-approved v3 TV identity and renewable login activated
  after tester removed an older Kellie's HA entry. Earlier login activation
  failed twice; safe replace/re-pair UX still needed, and stable old entry
  should be checked for regression.
- **PASS:** Android microphone permission granted in the first-run wizard.
- **PASS:** Signed QA app TALK captured "Turn on the office lights"; Home Assistant
  turned the office lights on and Kellie's Voice spoke the response (real TV).
- **PASS (local UI):** Tester selected all six QA themes on physical onn:
  Copper Glass, Compact Charcoal, Aurora Glass, Night Signal, Neon Obsidian,
  and Jade Terminal; all appeared to display correctly.
- **PASS (theme persistence):** Tester force-stopped and reopened QA with a
  selected theme and confirmed the same theme returned automatically.
  Voice overlay theme consistency and HA style sync are **not yet verified**.
- **PASS:** Display over other apps granted to QA package.
- **PASS:** Opt-in TV alerts receiver connected; HA diagnostic sensor
  `binary_sensor.living_room_qa_tv_alert_receiver_connected` was `on`.
- **PASS:** Real HA-targeted text announcement visibly appeared over the TV.
  Earlier not-seen report was simply observing the wrong area of the screen.
- **PASS:** Targeted `show_camera` driveway snapshot appeared. Refresh cadence
  was requested but was **not** separately verified on hardware.
- **PASS:** Targeted `show_live_camera` driveway showed actual moving live
  video, not a frozen still.
- **FAIL (expected limitation, issue #264):** Physical remote Back moved
  the underlying dashboard instead of closing the HA-triggered live camera
  overlay. Normal popup has `FLAG_NOT_FOCUSABLE | FLAG_NOT_TOUCHABLE`, by
  design, to avoid stealing controls from streaming apps. Do **not** flip
  the flag globally. Design a separate **opt-in interactive** camera mode
  before claiming Back-button camera dismissal.
- **PASS:** Targeted `kellies_voice.hide_camera` issued to close the QA camera;
  the tester confirmed that the camera disappeared from the real TV.
- **PASS:** Ordinary QA app close/reopen preserved Connected and Authenticated,
  without new pairing. Alert receiver remained ON in HA. This is **not** a
  confirmed Android force-stop; the receiver may remain alive separately.
- **PASS:** Tester force-stopped and reopened signed QA; login remained
  Connected and Authenticated with no pairing. HA receiver sensor history
  recorded OFF at 18:17:50 EDT and ON at 18:17:59 EDT, confirming a
  9-second disconnect/reconnect. Fresh targeted HA announcement was
  visibly displayed by the TV after recovery: **full force-stop alert-delivery PASS**.
- **FAIL (signed QA build 55, reboot):** With TV returned to home screen and
  QA app not manually opened, HA alert receiver switched OFF at 18:23:52 EDT
  and stayed OFF on repeated checks. The existing boot receiver ignored the
  active v3 renewable-login vault and only checked legacy manual credentials.
  Draft-branch source fix and regression policy tests committed; **not installed
  or physically retested yet**. Android background-start restrictions might
  also affect TV reboot behavior.
- **PASS:** Manually opening QA after reboot restored authenticated receiver;
  HA confirmed it turned ON at 18:26:34 EDT without re-pairing. This is
  **manual recovery**, not successful background auto-start. Targeted post-reboot
  announcement was visibly displayed on TV after the tester watched:
  **post-reboot manual recovery and real alert delivery PASS**.
- **Not tested:** manual camera dismissal via physical remote, audio policy,
  screensaver interactions, HA and Wi-Fi outage recovery, token
  renewal/revocation, and end-to-end release security review.

## Blockers before any public prerelease

- [ ] Independent security review (#214) of real dedicated HA normal Users
  permissions and the owner approval, token transfer/renewal/revocation
  lifecycle. Normal HA Users is NOT truly entity-scoped.
- [ ] Replace separate `kellies_voice_v3qa` test integration with a reviewed,
  production-ready supported onboarding path in the matching HACS component.
  Today's signed **release** APK intentionally does not expose this QA path.
- [ ] Keep HTTPS-only credential renewal; local HTTP-only login remains
  research issue #262. No implicit downgrade.
- [ ] Match signed Android and HA versions, installation migrations,
  complete release notes, images, docs and signed QA provenance;
  green CI on the exact final candidate SHA.
- [ ] Explicit maintainer approval before a `-dev.N` public prerelease.
  Stable v0.16.14 must remain Latest until a separately approved stable release.

**Reporting:** Record pass/fail and screenshot only sanitized app UI.
Never share refresh/access tokens, owner IDs, camera URLs, private home
camera images or signing keys.
