# v0.17.0 combined candidate: onn 4K Pro acceptance checklist

**Status: Draft PR #263 only. Not a public release.** The UI and secure
onboarding branches have been integrated on a separate review branch.
A green CI run is necessary but not sufficient. Physical TV signoff and
security review are mandatory.

## Install safely

- [ ] Run the private signing workflow manually on
  `integration/v0.17.0-combined-qa` with `publish_release=false`.
  Its `kellies-voice-qa-signed` artifact is the non-debuggable
  `com.example.tvvoiceprobe.qa` package with versionCode 55.
  **No public release or tag.** The normal PR test APK instead uses
  disposable `com.example.tvvoiceprobe.debug` signing, which can conflict
  when updating an older debug install.
- [ ] Update *only* the isolated `kellies_voice_v3qa` HA component from
  this PR's QA kit, preserve `configuration.yaml` and the separate
  stable `kellies_voice` HACS integration. Run `ha core check` and restart.
- [ ] Confirm old signed stable Kellie's Voice still launches and functions.
  **Do not uninstall stable or clear its data.**
- [ ] For a fresh signed QA install, pair again: the QA package has its
  own Android Keystore, pairing identity and credentials, separate from
  the existing debug beta. Never copy secrets between packages.

## First-run wizard: physical remote

- [ ] On first ordinary QA launch, welcome screen appears (not on star-button
  overlay shortcuts); readable on 720p/1080p; D-pad moves clearly between
  all buttons. Back and Skip never trap the user or start the mic.
- [ ] Secure pairing screen opens only when clicked. Compare eight digits
  with HA, press physical TV remote OK, approve by signed-in HA owner,
  choose dedicated login knowingly. Confirm TV activates and HA reports
  owner login success. Wrong code, cancel, timeout never issue a credential.
- [ ] Return to wizard: connection status becomes ACTIVATED. Confirm owner
  has been warned normal HA Users role has broad control over all entities.
- [ ] Request RECORD_AUDIO: Android prompt appears on first request;
  navigating back after allowing or denying still works. Grant alone must
  not record audio, turn on wake word or launch an overlay.
- [ ] Request Display over other apps: Android Settings opens to *QA package*.
  After returning, status reflects the actual system permission. If denied,
  receiver stays OFF.
- [ ] Skip / Finish closes wizard permanently for this installation; reopen
  under Compose > Home Assistant > First-time setup wizard (pair TV and
  grant permissions).

## v0.17.0 Quick Actions icon addition (pending hardware verification)

- HA returns only an authorized per-TV `slot`, `label` and bounded MDI
  `icon` name, never an entity ID, URL, token or arbitrary service call.
- Auto uses the target entity's HA MDI icon when available; otherwise a
  light/scene/script fallback. A per-button HA `Icon` dropdown can override
  Auto (Lightbulb, Movie, Home, Fan, Camera, Star, Script, etc.).
- The TV renders familiar icon families from local symbols without fetching
  image files. Unrecognized MDI names use a generic symbol; the exact MDI
  vector artwork is **not** bundled.
- Release QA must confirm correct icons/labels after update, restart and
  reconnect, and correct Home Assistant device-page settings persistence.
  Do not edit or execute any security-critical entities during testing.

## v0.17.0 screensaver camera login regression (2026-10-31)

- **FAIL on signed QA build 55:** The installed owner-approved v3 QA app
  authenticated Assist, displayed HA Quick Actions after the separate HA
  mapping fix, and remained connected for alerts, but native screensaver
  cameras displayed `Sign in to Home Assistant to load these cameras.`
- **Root cause found in source:** `ScreensaverBoard.signedIn()` only read the
  old manual `CredentialStore`. v3 pairing deliberately does not place
  renewable credentials there. The previously installed QA APK predates
  the screensaver fix.
- **Source patch (PR #270):** read the renewable Keystore grant on a
  background thread; use it for HA camera snapshots and live HLS. Fail
  closed if renewal is denied, with no manual owner-token fallback; keep
  manual-only screensavers unchanged. Re-authorize before the 30-minute
  access-token expiration during long-running dreams.
- [ ] Install a freshly signed QA APK from the patched combined-branch HEAD,
  preserving the app's existing Keystore login. Do **not** uninstall QA.
- [ ] Verify both `Preview screensaver` and Android's real idle dream
  show all configured snapshots / Live 4 without a manual-token prompt.
- [ ] Verify entering/exiting full-screen camera, audio on selected stream,
  physical Back and automatic return to the grid.
- [ ] Leave dream running more than 35 minutes: ensure snapshots and
  live tiles reconnect after renewal without signing in or leaking a token.
- [ ] Test HA offline, refresh-token revocation and user cancellation:
  no camera credentials fall back to legacy owner login. Confirm reconnect
  after HA returns only if a still-valid dedicated TV grant exists.
- [ ] Confirm stable TV package and public `main` are unchanged.
